# 验证轮发现的三个修正 + 一条环境事实（verification-fixes）

Status: ready-for-agent

## Problem Statement

收尾轮的浏览器验证（closeout 的 01–05）在走真实界面时撞出三件产品侧的问题。它们都没有被修，只记在几张已 `resolved` 工单的「附带发现」里——**看起来像已收尾**：

1. **新建事项时填的「进展」会被服务端丢掉。** 用户填了进展、界面也确实把它发了出去，保存回来的这条事项进展却是空的，且没有任何提示；必须再进一次编辑框补写才生效。这是静默的数据丢失，而且它落在本轮刚验过的对话框流程上——测试全绿、界面走通，字段却在写入层掉了。现有测试照不到它：它们只断言「不带进展时是空的」与「编辑能写入」，没有一条断言「新建时就带进展」。
2. **删账号时的「转移事项」依赖 `window.prompt()`。** 在内嵌 webview 里这个 API 被禁用（本轮在内置浏览器实测：点击后只弹一条 `prompt() is not supported.` 的错误提示，流程走不下去），于是这条管理路径只在普通浏览器里可用。
3. **会话失效后界面停在「僵尸登录态」。** 服务端判定会话失效时，顶栏仍显示着账号、日历还在，但下一步动作统一报「请先登录」，且永不回到登录页。用户只能靠猜。

另有一条环境事实没有落到唯一出处：**会话 cookie 只按主机名区分、不按端口**，所以同机并行跑多个实例时，任何一方在浏览器里登录都会把别人的登录态顶掉——它正是第 3 条的触发器，也是并行验证时「登录态莫名丢失」的根因。

## Solution

- 新建路径把进展两列真正写进库，并补一条**会先失败**的测试，把这类「校验层备好了值、写入层漏了列」的漏写挡住；
- 转移目标的选择换成 admin 对话框内的列表视图，不再依赖 `prompt()`，取消路径保留；
- 把「哪些响应意味着会话已失效」收敛成一个纯函数并接进请求层：只有 401 触发；失效时关掉对话框、清状态、回登录页并说明原因；403/409 等一律不触发；
- 环境文档补一节（症状 / 成因 / 规避），并交叉引用第 3 条。

## User Stories

1. 作为填过进展的人，我想要新建事项时填的进展保存后还在，这样我不必再进一次编辑框补写。
2. 作为填过进展的人，我想要进展在新建与编辑两条路径上行为一致，这样我不必记住「哪个框填了才算」。
3. 作为项目维护者，我想要这类「校验层备好了、写入层漏了」的漏写被一条会失败的测试挡住，而不是靠浏览器里偶然撞见。
4. 作为下一个接手的人，我想要那条测试读起来就能说明它防的是什么，这样我不会把它当成装饰性的断言。
5. 作为管理员，我想要在一个真正的对话框里从候选账号中点选转移目标，这样在禁用 `prompt()` 的环境里我照样能删账号。
6. 作为管理员，我想要转移目标列表显示候选账号名、并且能取消，这样我不会因为点错而把事项转给错的人。
7. 作为管理员，我想要「唯一 owner 的未归档事项必须先转走」这条约束不因为换界面而改变，这样删账号的后果仍然是我预期的那份。
8. 作为使用产品的人，我想要会话失效时被明确告知并送回登录页，这样我不会对着一个假装还登录着的界面反复点。
9. 作为使用产品的人，我想要提示里说清原因（登录已失效），这样我知道重新登录就能继续，而不是以为数据坏了。
10. 作为使用产品的人，我想要正在编辑的对话框在会话失效时被关掉，而不是留一个保存必定失败的框，这样我不会白填一遍还以为能提交。
11. 作为 `user` 角色的账号，我想要「无权处置他人事项」这类 403 不被当成会话失效，这样我不会被莫名踢回登录页。
12. 作为项目维护者，我想要「哪些响应意味着会话结束」只有一处定义，这样以后新增接口不会各写一份判断。
13. 作为并行做验证的人，我想要环境文档写明 cookie 只按主机名不按端口、以及换主机名的规避方式，这样我能解释「登录态为什么莫名丢了」。
14. 作为项目维护者，我想要这三条修正的来源工单被回指，这样证据链不断。

## Implementation Decisions

**A. 新建路径的进展**

- 校验/归一化层已经为新建路径备好了进展的值（有值即字符串、空白即空），漏的是写入层：创建事项的插入语句没有把「进展」与「它的更新时间」两列写进去。修法是把两列加进插入语句，语义与更新路径一致——有进展才记更新时间，没进展两列都是空。
- 不改表结构、不做迁移、不回填历史数据：这两列早就在表上，只是新建路径从不写。
- 测试必须**先失败**：断言「新建时带进展 → 落库且更新时间是 ISO 时间」与「新建时只填空白 → 两者都为空」；先跑一次确认它红、且红的原因正是「进展是空」，再改插入语句。
- 这个 bug 的成因是「值备好了但没被消费」，因此测试要断言**落库后的返回字段**，而不是断言插入语句本身。

**B. 转移目标的对话框视图**

- 在 admin 对话框内部做一次视图切换：把候选账号渲染成一列可点条目，点选后走既有的转移接口，并提供取消。不新增对话框元素、不改动删除账号的其余流程与约束。
- 复用既有的对话框生命周期（按次注册监听、自动解开）与既有的事件委托约定，不引入新的监听方式——这里曾经出过「监听器叠加、确认框弹 N 次」的 bug，结构上不再开新口子。
- 为什么不用 `prompt()`：它在部分内嵌 webview 里被禁用，且项目其余交互一律是对话框，风格不一致。
- 界面行为按项目惯例在浏览器里手验，必须覆盖「点选一个目标」与「取消」两条路径。

**C. 会话失效的单一判据**

- 把「这个响应是否意味着会话已失效」收敛成一个**纯函数**（只有 401 成立），由请求封装层调用，交给应用层注册的处理器收尾：关闭打开的对话框、清空状态、回到登录页、提示「登录已失效，请重新登录」。
- 明确**不**触发的：403（无权处置他人事项）、404、409（版本冲突）、400（字段错误）、5xx、以及没有状态码的网络错误。这条边界要由测试固定住——把 403 当成会话失效会误伤一个正常登录着的 `user`。
- 启动探测与登录失败都不会误触发：未登录时启动探测仍返回 200（服务端在鉴权之前就处理它），登录失败返回的是别的状态码。
- 不做「保留草稿、登录后继续」：会话已失效时保存必然失败，留着半开的编辑框只会让人白填一遍。
- 服务端会话机制（有效期、续期、多设备）本次不动。

**D. 环境事实**

- 环境文档增一节：**症状**（页面显示着登录态、动作却报「请先登录」，而服务端会话表里没有对应那一行）、**成因**（会话 cookie 只按主机名区分、不按端口，同机多实例互相顶掉）、**规避**（给每个身份一个不同主机名，或接受它并在每次动作前确认登录态），并交叉引用 C 的修正。

**术语**：一律用词表词汇——事项、owner、邀请、进展、归档、账号、角色、注册申请；「管理员」是口语合称，特指最高权限时写 `admin`。本次不新增术语，词表不改（产品名对齐是另一张票的事）。

## Testing Decisions

- **好测试**：只断言外部可观察行为（接口返回的字段、界面上的文案与状态），不碰实现细节；一条测试读起来应当能说明它防的是什么。
- **A —— 领域层**：沿用同一文件里既有的进展用例与内存库脚手架（每例一套实例），先例就是它旁边那条「默认没有进展」。新增两条（带进展落库、空白视为空），并先确认它们会失败。
- **C —— 纯函数层**：进现有零依赖测试套件。断言集：401 → 结束会话；400 / 403 / 404 / 409 / 5xx / 无状态码 → 不结束。先例是前端流程决策那类纯函数测试（它已覆盖 409 的分支）。
- **B —— 浏览器层**：没有可测的纯逻辑（序号解析随 `prompt()` 一起消失），按项目惯例手验并记录，先例是本轮 01–06 的证据表与管理面板那票的界面路径验证。
- **C 的界面行为也在浏览器层手验**：真的要制造一次会话失效（让同一主机名上的另一实例顶掉 cookie，或直接清掉 cookie），再点任意动作，确认落到登录页并看到提示，且**不再出现**顶栏假装登录的僵尸态。
- **回归**：全量测试套件（现 88 项 + 新增）全绿。

## Out of Scope

- 服务端会话机制：有效期、续期、多设备并用、服务端主动踢出。
- 「会话失效后保留草稿、登录后继续编辑」。
- 为 B 写自动化浏览器测试（项目零依赖、无浏览器测试运行器，本轮不引入）。
- `prompt()` 之外的 admin 流程重构。
- closeout 那两张还开着的票（产品名统一、收口核对），以及 `master` 分支处置、推送到远端（代理未运行）——各自归属不变。

## Further Notes

**与 closeout「收口核对」票的冲突要留意。** 那张票有一条验收是「全仓没有 `claimed` / `needs-triage` 残留」，本 spec 一开工就会让这句话暂时不成立。它应当按「closeout 本轮自己的工单」来理解；执行时不要顺手把它关掉，也不要为了让它成立而推迟本轮的工单发布。

**三条修正的出处**（新工单应回指，别让证据链断）：A 来自 409 验证那票的附带发现，而那票自己写明「若维护者认可应另开工单，不要让它随本票被当作已收尾」；B 与 C 来自管理面板那票的「环境限制与未做」；D 来自 409 那票附带发现的第 2 条——那票把「是否并进环境文档」留给维护者定，本次决定：并进去。

**顺序建议**：A 先做（唯一的数据丢失，测试落点现成）→ C（纯函数 + 请求层接线）→ B（界面改动，独立于前两者）→ D（文档）。A 与 C 互不阻塞，可以并行。

**风险**：B 改的是一条会真的删除账号、转移事项的路径，手验请在一次性实例的临时账号上进行，不要在真实库上试删账号。C 的验证要真的让会话失效，不能只看代码。

**本轮的完成标志**：三条修正各自的证据写进工单、全量测试全绿、环境文档那一节落盘、closeout 的两张票按原样继续。
