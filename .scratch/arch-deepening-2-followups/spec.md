# 第二轮架构深化的后续项（arch-deepening-2-followups）

Status: ready-for-agent

## 这个 effort 是什么

第二轮架构深化（`arch-deepening-2`，八张票、两个 tag）收口时，主 agent 与各票报上来的**四条后续项**加**一条老账**。它们都是已知的、有具体证据的小口子，不是新功能。

来源分别是：工单 05 的「主 agent 核对」里带实测数据报告的两处同类缺口（删事项 / 删账号的级联通知不完整）、工单 06 冒烟时记下的一条产品取舍（owner 名单没有默认勾选）、工单 03 追认时记下的一处依赖方向（`auth.js → sse.js`），以及两轮来被标记过两次的一条环境事实缺口。

## 五张票与顺序

| 票 | 内容 | 阻塞于 |
| --- | --- | --- |
| 01 | 变更词表与 owner 差分抽成 `server/changes.js` | 无（**要先做**：02/03 都往词表里加东西） |
| 02 | 删事项级联删掉待接受邀请时，通知受影响的被邀请人 | 01 |
| 03 | 删账号摘掉共享事项的成员资格时，产出 `itemOwners` 变更 | 01、02（同碰 `items.js`） |
| 04 | 新建事项时预勾选自己 | 无 |
| 05 | 环境文档补「原生 `confirm` 可用」 | 无 |

## 并行方案（按文件脚印）

- **W1 三条线并行**：01（`server/{sse,items,invites,accounts,auth}.js`）∥ 04（`public/itemform.js` + `app.js`）∥ 05（`docs/agents/local-environment.md`）——零文件重叠。
- **W2**：02（`server/items.js`）。
- **W3**：03（`server/accounts.js` + `items.js` 的新 API）。
- 02 与 03 都在服务端且都要碰 `items.js`，**不能并行**（这是文件重叠决定的，不是偏好）。

给并行 agent 的硬规则沿用上一轮（共享工作区）：只改自己票里的文件；**提交用 pathspec**（`git commit -m "…" -- <自己的文件>`），绝不用 `git add -A`；不跑 `stash` / `checkout` / `branch` / `reset` / `clean`；撞上 `index.lock` 等两秒重试；不启动服务、不用浏览器；`npm test` 判断标准是「没有 fail」且「新增断言全过」。

## 验收标准（每张票一律）

先有**会红的判据** → 改 → **全绿**（当前基线 278 项 + 新增）。能复现的先复现。提交前跑全量套件，一笔提交进 `main`。本轮的收口不做浏览器冒烟——01–03 是投递/通知的判据，可在 `node:test` 里断言（中枢已经是可注入的 module，见工单 02 of arch-deepening-2）；04 是界面默认值，其纯函数部分可 headless 断言，真实界面的确认留给下一次段界冒烟。

## 与既有决策的关系

- 01 是**兑现** arch-deepening-2 工单 03 里那条被追认的依赖的替代方案（当时记下：抽独立的 `server/changes.js`，成本很低，本轮不做）。抽完之后那条记在案的理由就失效了，票里要写明这一点。
- 02、03 补的是**同类缺口**：arch-deepening-2 工单 05 记过两处「级联删除后受影响的人收不到通知」，那两张票当时因超出范围没有覆盖。
- 04 是**产品取舍**：管理员建事项时 owner 名单没有默认勾选（改动前后一致，非回归）。本轮的立场：预勾选**自己**——常见情形就是「给自己建一条」，而勾选组对管理员是可见的，取消勾选的成本低于漏勾导致 400 的成本。这条立场要写进票里，用户若否决只需回退这一条断言。
- 05 补的是环境文档的**唯一出处**：IAB 里原生 `confirm` 可用（`prompt()` 被禁用）这条事实目前只写在 arch-deepening-2 的两张工单里。

## 范围之外

- 不重做 arch-deepening-2 的八个候选（已收口、有 tag）。
- 不动「可见性在服务端过滤」这条不变量、不改 SSE 传输方式。
- 不为 04 新增产品概念（例如「默认 owner」这样的设置项）；它只是一个预勾选。
