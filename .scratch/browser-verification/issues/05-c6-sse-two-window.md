# c6 — 双窗口 SSE 实时同步（无需刷新）

Status: resolved

交接文档把这一项标为「最值得做」，本次以可证伪的方式验证，而非只看「有没有出现」。

## 验收标准

窗口 A 新建事项，窗口 B 无需刷新即出现。

## 结论

**通过。**

## 证据设计

「没刷新也出现了」很容易被误判——只要观察者自己触发过一次刷新，或页面恰好重载过，看起来也会「出现」。因此本次加了两道独立佐证：

1. **`MutationObserver`**：在窗口 B 的 `#grid` 上装观察器，记录每次 DOM 变更的时间戳。若色块是被刷新出来的，观察器不会有记录（或记录会出现在导航之后）。
2. **`performance.timeOrigin`**：文档一旦重载或重新导航，该值必然改变。它不变即证明窗口 B 从未重载。

## 实测数据

窗口 B 基线（窗口 A 尚未创建任何事项，此前的事项已被 c4 归档）：

```
gridBlocks = []   today = "今日任务 0"   mutations = 0   timeOrigin = 1789646523901.9
```

在窗口 A 经界面新建 `验证事项C6` 后：

- 窗口 A：`gridBlocks = ["admin: 验证事项C6"]`，`today = "今日任务 1"`
- 窗口 B（**首次轮询即已更新**，全程未调用 `reload()` / `goto()`）：
  - `gridBlocks = ["admin: 验证事项C6"]` ✓
  - `today = "今日任务 1"` ✓
  - `mutations = 1` —— 观察器恰好记录到一次实时 DOM 变更，发生在读取前 568ms ✓
  - `timeOrigin` **未变**（`1789646523901.9`）✓

即：变更经由 SSE 推送到达窗口 B 并触发了真实 DOM 更新，且窗口 B 未发生任何重载。

## 附带确认

IAB 各标签页共享 cookie，窗口 B 打开即处于登录态（`whoami = admin（admin）`），无需二次登录。这既是测试前提，也说明会话是按 cookie 而非按标签页隔离的。
