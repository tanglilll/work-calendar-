# c4 — 归档二次确认，确认后从日历与侧栏消失

Status: resolved

## 验收标准

归档二次确认框 → 确认后事项从日历与侧栏消失。

## 结论

**通过**，且比原定验收多验了一条「取消」路径。

## 证据

点击日历色块打开编辑对话框，实测：

- 对话框标题 `编辑事项`，标题字段预填 `验证事项C2`，`标记完成` 与 `删除` 按钮各存在 1 个

### 取消路径（确认框返回 false）

`window.confirm` 被调用，文案精确为：

```
确认把「验证事项C2」标记为完成？

完成后该事项会从日历和所有面板消失，且无法撤销。
```

返回 `false` 后：对话框仍开、`gridBlocks` 仍为 1 条、侧栏计数不变（今日任务 1 / 截止提醒 1）。**取消是真正的无操作**，不会误归档。

### 接受路径（确认框返回 true）

- 对话框关闭（`open = false`）
- `#grid [data-item-id]` 变为 `[]` —— 从日历消失 ✓
- 侧栏「今日任务」`1 → 0`、「截止提醒」`1 → 0` —— 从侧栏消失 ✓
- toast 显示 `已标记完成（已归档）` ✓

## 方法学说明（重要）

- 点击由 `locator.evaluate(el => el.click())` 派发，非真实指针事件（原因见 `spec.md`）。
- `window.confirm` 由页面内 spy 拦截，以便断言**文案内容**并确定性地控制返回值。IAB 的 JS dialog 接口只暴露 `accept()/dismiss()`，**读不到 message**，所以文案断言只能靠 spy。这意味着「原生确认框的视觉呈现」未被观测；被验证的是应用确实调用了 `confirm` 且按返回值分支。
- 归档不可逆，因此本次没有尝试「归档后再编辑」这类边界。

## 复现

点 `#grid [data-item-id]` → 点 `[data-act="archive"]` → 处理 `confirm`。
