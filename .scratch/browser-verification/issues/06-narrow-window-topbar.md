# 窄窗口下顶栏文字竖排与横向溢出

Status: resolved

做 c2–c6 时顺带复现的既有缺陷（交接文档 §5 已描述，本次给出了量化数据）。**未实施任何修复**——修法涉及取舍，需先决策。

> 2026-09-18 状态推进：修法已定并实施，**第二轮浏览器验证复测通过，本工单关闭**（见文末「修复」「复测」两节）。本文档的「现象」「证据」两节保留修复前的原始记录，不改写。

## 现象

窗口变窄时顶栏元素逐字换行：`日程看板` → 竖排四行，`+ 新建事项` → 五行。

## 证据

视口宽度用 `tab.setViewportSize()` 调整，行数用 `Range.getClientRects().length` 计数（比目测截图精确）：

| 视口宽 | 日程看板 | + 新建事项 | 管理 | 登出 | 顶栏溢出 |
| --- | --- | --- | --- | --- | --- |
| 1280 | 1 行 | 1 行 | 1 行 | 1 行 | 否 |
| 700 | 2 | 2 | 2 | 2 | 否 |
| 520 | 4 | 5 | 2 | 2 | 否 |
| 420 | 4 | 5 | 2 | 2 | **是**（`scrollWidth` 495 > `clientWidth` 405） |

恢复到 1280 后全部回到 1 行，说明是自适应布局的宽度不足，不是渲染残留。

**700px 就已经开始换行了**——这个宽度在分屏或小窗口下很常见，所以缺陷的触发门槛比「窄窗口」这个说法暗示的要低。

## 交接文档没提到的一点

420px 时顶栏**横向溢出**（495 > 405），已不只是换行：按钮会被裁掉一部分。这让问题从「不好看」变成「点不到」。

## 建议修法（未实施）

`public/style.css` 的 `.topbar` 一节，给 `.topbar button` 与 `.brand` 加：

```css
white-space: nowrap;
flex-shrink: 0;
```

但**单加这两条会把溢出加重**：文字不再换行，内容却依然超宽，700～900px 区间可能从「换行」直接变成「溢出裁切」。所以需要一并决定窄屏降级策略，可选：

- 顶栏改为横向可滚动（`overflow-x: auto`），保证任何宽度都不裁切；
- 或窄屏折叠次要按钮（`管理` / `登出` 收进菜单），只保留 `+ 新建事项`；
- 或干脆给 `.topbar` 设 `min-width` 并让整页横向滚动，明确本项目不适配窄屏。

这属于产品取舍，不是纯 CSS 修补，故留作 triage 决策。

## 修复（2026-09-18）

**决策：整块折行**，未采用上面列的三个选项。

- `.topbar` 加 `flex-wrap: wrap`——宽度不足时整块挪到下一行，而不是把文字逐字拆开；
- 新增 `.topbar > * { flex-shrink: 0; white-space: nowrap; }`——顶栏的每一块内部不再断行、也不被压扁；`white-space` 会继承到块内的按钮，所以按钮文案同样不拆；
- `.topbar-right` 也加 `flex-wrap: wrap`——它在极窄宽度（低于本次已测的 420px）下能自行分行，而不是把按钮顶出去。

上面那条「单加 `white-space: nowrap` 会加重溢出」的担心之所以不成立，是因为同时加了容器级的 `flex-wrap`：内容超宽时整块换行，而不是留在原地被裁。

产品口径写进 README「已知限制」：**≥700px 是可用宽度**，更窄只保证不裁切、按钮可点（日历 7 列在 420px 下每格约 55px，色块文案本就读不了，那是列数决定的，与顶栏无关）。

为什么不用另外三个选项：横向滚动要让用户自己发现「顶栏能滚」；折叠菜单要在这个刻意保持前端轻的零依赖项目里新增组件、开关逻辑与键盘可达性；声明不适配则把代价转嫁给分屏用户——700px 换行说明分屏是常见用法。

**复测已做（2026-09-18）**：见下一节；复测通过，本工单关闭。


两点判断记在这里（`/code-review` 的 Spec 轴追问过）：

- **不走收尾 spec 的「应急口径」。** spec 写的是「若 420px 下仍横向溢出，则回退到『顶栏横向滚动』或『声明不适配窄屏』」。这里没有回退，理由是：那条口径针对「决策本身撑不住」，而这次撑不住的是一条**互相抵消的 CSS 规则**——`.topbar > *` 的 `flex-shrink: 0` 让按钮组无法收缩，于是它内部那条 `flex-wrap: wrap` 永不触发。让按钮组可收缩之后，已定决策（整块折行、块内不拆字、纯 CSS 无 JS）**原样成立**：判据没有放宽（420px 无溢出、按钮完整可点，全部重新测过），也没有引入被否掉的三个方案中的任何一个；回退到「横向滚动」反倒会退回一个已被明确否掉的方案。
