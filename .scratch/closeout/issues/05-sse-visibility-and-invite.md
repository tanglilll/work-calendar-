# 05 — SSE 可见性与邀请

**What to build:** 用第二个账号在另一个标签页观察三件事：`user` 角色收不到他人事项的事件；被邀请人待接受期间看不到该事项；接受邀请后**不刷新**即出现。第三条顺带验证一条从未在界面上出现过的领域规则——「邀请不是参与者状态」。

**Blocked by:** None — can start immediately.（建议与 02、03、04 共用一个浏览器会话与一个实例；本票需要一个 `user` 角色账号，走真实的申请→批准路径造出来）

**Status:** ready-for-agent

- [ ] 他人新建或修改事项时，`user` 账号的窗口里**不出现**该事项——日历与三个侧栏面板都没有它（这是本轮最要紧的一条：可见性由服务端过滤，前端不被信任）。
- [ ] 被邀请人**待接受期间**：日历与三个面板里都看不到该事项，只在顶栏「邀请」入口（带角标）里看到它的标题、日期与发起人。
- [ ] 接受邀请后，该事项出现在被邀请人的窗口里，**无需手动刷新**；同时它成为 owner 之一。
- [ ] 拒绝邀请后该事项不出现，且发起人可以再次邀请同一个人。
- [ ] 证据写进本工单，并注明该账号的角色确实是 `user`——不要用被提权过的演示账号，「提权过的账号收不到/收得到什么」与普通成员不同，会得出错误结论。
