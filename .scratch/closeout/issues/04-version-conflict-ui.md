# 04 — 409 冲突的界面表现

**What to build:** 两个窗口编辑同一条事项、先后保存，确认后保存的一方看到冲突提示、且先保存者的改动没有被静默覆盖。乐观锁是「不静默覆盖他人改动」这项承诺的全部实现，它的界面表现从未被观察过。

**Blocked by:** None — can start immediately.（建议与 02、03、05 共用一个浏览器会话与一个实例）

**Status:** ready-for-agent

- [ ] 后保存的一方看到明确提示（大意「此事项已被他人修改，请刷新后重试」），而不是静默成功、也不是无声失败。
- [ ] 先保存的一方的改动**仍然在**：冲突没有把对方的改动覆盖掉。
- [ ] 冲突之后对话框的行为是明确的——关闭、或保持可编辑但提示清楚——不存在「看起来保存成功、实际没保存」的中间态。
- [ ] 归档路径上的冲突同样被观察到（它与保存共用同一份版本校验）。
- [ ] 证据写进本工单，并注明两个窗口用的是同一账号还是不同账号——两种情形下「谁看得见什么」的推理不同。
