# 03 — 管理面板验证：注册申请 → 批准 → 登录 + 改角色

**What to build:** 在一次性隔离实例上，把「访客提交注册申请 → 管理员批准 → 新账号登录」这条团队拿到账号的唯一路径，连同管理面板的其余动作，在真实浏览器里走一遍并记录观察值。这条路径此前只有领域逻辑与接口层的测试，界面接线从未被操作过。

**Blocked by:** None — can start immediately.（建议与 02、04、05 共用一个浏览器会话与一个实例）

**Status:** ready-for-agent

- [ ] 提交注册申请之后**账号并不存在**：用申请时填的用户名登录会失败；管理面板里能看到这条待批准申请，含申请人自选的用户名与备注。
- [ ] **批准那一刻账号才生成**：角色是 `user`，用申请时填的密码能登录成功。
- [ ] 拒绝申请后记录消失（不留下一个否定的状态），且同一个用户名可以重新申请。
- [ ] 改角色为 `manager` 后，该账号的可见范围立刻扩大到全部事项；降回 `user` 后，他人的事项立刻从其界面消失，**不需要手动刷新**。
- [ ] 删账号路径的界面提示被观察到：它作为唯一 owner 的未归档事项必须先转移，转移完成后删除成功；与别人共享的事项只是把它从 owner 名单里摘掉、事项本身留着。
- [ ] 归档视图在界面上确认为**只读**：能看到已归档事项，但没有任何可改动它的入口。
- [ ] 证据写进本工单：环境（端口、库、账号）、操作步骤、观察到的具体现象与结论；凡是用到绕过浏览器指针管线的点击方式，按方法论文档的要求标注出来。
