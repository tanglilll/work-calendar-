# 02 — 完成度与紧急重要度两个字段 + 按象限分组的表格视图

**What to build:** 对照用户给的「工作日志」表格截图，把能用本项目领域语言表达的部分落地：两个可写字段（完成度、紧急重要度）、一个表格视图（分组 / 筛选 / 排序 / 统计），其余列由日期与归档时间派生。

**Blocked by:** None — can start immediately.

**Status:** resolved

- [x] **完成度 `percent_done`**：INTEGER 可空，0–100 的整数；进 `ITEM_FIELDS`（接受数字或数字字符串，空 / `undefined` / `null` → `null`，非整数或越界 → `完成度必须是 0–100 的整数`）。
- [x] **紧急重要度 `quadrant`**：TEXT 可空，白名单四值 `重要且紧急 / 重要不紧急 / 紧急但不重要 / 不紧急不重要`；空 = 未标注（不是第五个象限，也不是「不紧急不重要」）。
- [x] 两列在 `server/db.js` 的建表语句与 `ensureColumns` 里各加一次（新库 + 老库两条路径），**不加 SQL CHECK**——校验唯一落点是 `ITEM_FIELDS.parse`，这样两条路径行为一致。
- [x] **状态 / 预计所需天数 / 实际完成日期 / 是否按时交付全部派生、不落库**：已完成 = 已归档；今天 < 起始 → 待开始；今天 ≥ 截止 → 已逾期（截止当天即算逾期，与 README 的侧栏逾期基线同源）；其余 → 进行中。天数 = 截止 − 起始 + 1；按时交付只对已归档行有值。
- [x] `public/tableview.js`（新文件，413 行）：派生纯函数 + 渲染各一处，纯函数能被 `node:test` 直接 import。
- [x] 列顺序同截图：任务描述 / 任务负责人 / 任务状态 / 完成度 / 预计所需天数 / 是否按时交付 / 项目进展描述 / 开始日期 / 预计完成日期 / 实际完成日期 / 紧急重要度；完成度画进度条，状态与象限是带状态的徽章，空值显示「—」。
- [x] 分组：按紧急重要度分组、可折叠、组头「记录数 N」，未标注单独成组殿后，空组不渲染。
- [x] 筛选与排序：状态 / 象限 / 关键词（标题、owner 用户名、进展）；按截止日期 / 起始日期 / 完成度升降。
- [x] 底部记录数统计；空列表显示「没有符合条件的事项。」。

## 结论

**截图里能用领域语言表达的部分全部落地；表达不了的两样明确不做并写进了 ADR。** 派生量不落库是本票最重要的取舍：状态、天数、按时交付都能从已有的日期与归档时间推出来，多存一份就多一处会不一致的地方；而完成度与紧急重要度是货真价实的新信息，只能存。
