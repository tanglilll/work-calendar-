# 04 — 象限次序按处理优先级、四象限配色、截止当天算「进行中」

**What to build:** 三处按用户反馈调整的展示口径：分组的默认次序、象限字样的颜色、以及「截止当天」落在哪一档状态。

**Blocked by:** None — can start immediately.

**Status:** resolved

**出处：** 用户在 2026-10-07 看完工单 02 的成品后提的两条反馈（次序与颜色、当天截止的状态）。

## 三条改动

**1. 象限的默认次序改成产品优先级。** 用户指定：**重要且紧急 → 紧急但不重要 → 重要不紧急 → 不紧急不重要 → 未标注**。原来按教科书的四象限次序（重要不紧急 排在 紧急但不重要 之前），现在按"要多快处理"排——马上做 → 分出去 → 排期 → 放着。落点在 `server/config.js` 的 `QUADRANTS`（顺序就是全站顺序：分组、筛选下拉、事项对话框的选项都读它，前端不另存一份），未标注依旧是殿后那一档。

**2. 每个象限的字样有自己的颜色。** 行内徽章与组头字样共用一套色号（`public/tableview.js` 的 `QUADRANT_CLASS` + `public/style.css` 的 `.q-*`）：马上做=红 / 分出去=橙 / 排期=蓝 / 放着=绿 / 未标注=灰。**按值配、不按下标**，所以以后调整次序不会串色；也不用参考截图里「橙 + 琥珀」那种近似配色，四个颜色必须一眼能分开。（参考图里「重要不紧急」是琥珀色，这里用了蓝色——橙与琥珀并排分不开。）

**3. 截止当天算「进行中」，不再算「已逾期」。** `statusOf` 从 `今天 >= 截止日期 → 已逾期` 改成 `今天 > 截止日期 → 已逾期`。这一改让状态列与侧栏「截止提醒」里**「已逾期」那一组**变成同一条判据（都排除当天），侧栏单列的「今天截止」在状态列里算「进行中」——两边都认为"当天还没过完，这件事还在做"。README 的「逾期基线」`due_date <= 今天` 是「截止提醒」两组之和的**汇总口径**，不是「逾期」的定义（词表也跟着把这条讲清楚了）。

## 连带改到的（同一件事的不同落点）

- `test/tableview.test.js`：截止当天的边界用例改成「进行中」；「已逾期的集合 === sidebar 的逾期基线」改成 === sidebar 的 `overdue` 组（两边都排除当天），并补一条「今天截止的那条不能被算作逾期」；状态筛选的期望值随之调整（原来落进「已逾期」的那条今天截止的事项，现在落进「进行中」）。
- `test/tableview.test.js` 新增三色号用例：白名单每个取值都有色号（拿 `server/config.js` 的 `QUADRANTS` 逐值核，**象限改名时红在测试里而不是界面上悄悄丢色**）、五种取值五种颜色、行内徽章与组头字样带同一个类。
- 文档：`CONTEXT.md` 的「逾期」「状态」「紧急重要度」三个词条、`README.md` 的「侧栏三个面板的口径」末段、`docs/adr/0003` 的 Consequences 与两条新决策、`public/tableview.js` 与 `public/sidebar.js` 的模块头注释。

## 结论

三处都只动展示与派生口径，**没有碰存储、接口与迁移**：象限次序是白名单数组的顺序，颜色是纯 CSS + 一张按值配的表，状态是纯函数里的一个比较符。全量 `node --test` **388 项全绿**（改动前 385，新增 3 条色号用例）。
