# 05 — 停用标签「紧急」，并让存量数据不被动

**What to build:** 把「紧急」从标签白名单里去掉；存量事项上已经写着的旧值不迁移、不抹掉、也不拦住保存。

**Blocked by:** None — can start immediately.

**Status:** resolved

**出处：** 用户 2026-10-07：「标签里的紧急可以被删除了」。它确实成了冗余——紧急与否已经由「紧急重要度」那张四象限表表达（`percent_done`/`quadrant` 那一轮加的），再留一个同名的标签就是让人在两处做同一件事。

- [x] `server/config.js` 的 `TAGS` 去掉「紧急」，并在注释里写清停用日期与理由、以及存量数据不迁移这条立场。
- [x] 新建与「设到别的事项上」一律拒绝：错误信息里列的白名单也跟着变成 `工作、个人、会议、出差`（提示语由 `TAGS.join` 派生，不是手写的，所以不会漂）。
- [x] **存量事项上已有的「紧急」不迁移、不抹掉。** 这一条要成立必须补两处——缺任何一处用户都会受伤：
  - **服务端（宽限）**：`items.js` 的 `tag.parse(raw, current)` 多收一个「这条事项的现值」，只放行「本来就是它」的那一条。没有它，表单总是把 tag 一起提交，改成只动标题也会 400（白名单一律拒）；这正是「停用取值把存量数据变成不可编辑」的那个坑。
  - **前端（看得见）**：编辑框把该事项自己那个不在白名单里的值补成一条选项、带上 `selected`、文案标「（已停用）」。没有它，`<select>` 会落回第一个选项「（无标签）」，用户根本没碰标签、一保存就被**静默抹掉**——21b42ba 那一类事故的镜像。
- [x] 边界写清楚：宽限**只认「本来就是它」**，不是给停用值开口子。字段表的注释也补上了 `parse` 的第二个参数是什么、为什么只有 tag 用它。
- [x] 文档：`CONTEXT.md` 的「标签」词条补上「白名单可以收窄」这条规则（停用的取值不再可选、存量旧值不迁移不抹掉、设到别处仍拒绝）；`README.md` 的规则一节把白名单改成 `工作/个人/会议/出差` 并说明停用与存量处置。
- [x] 测试：`test/items.test.js` 三条（新建传「紧急」→ 400 且提示里不再列它；存量事项把自己那条带回 → 放行且其它字段照改；把停用值设到别的事项 → 仍 400），`test/itemform.test.js` 两条（编辑态补出「紧急（已停用）」并选中；新建时不多出这条、白名单里的值照旧回显）。
- [x] 浏览器层实测（隔离实例 `127.0.0.2:4413`）：先直接写库造一条「收窄之前」的事项（`tag='紧急'`，接口现在建不出来），再在真界面里走一遍。

## 结论

**「紧急」从可选项里消失，但存量数据一点没动。** 这条改动本身只有一行（白名单少一个值），真正要设计的是「白名单收窄之后存量数据怎么活」：不动它，且不因为这次收窄而让那些事项变得不可编辑、或被静默改掉。所以多了一个显式的宽限（服务端）与一条看得见的选项（前端），两处都写了它们防的是什么。

### 证据

浏览器（隔离实例，DOM 读值 + 库里的行）：

```
编辑框里的标签下拉（存量事项）：
  |（无标签） / 工作|工作 / 个人|个人 / 会议|会议 / 出差|出差 / 紧急|紧急（已停用）|选中
  → select 的 value 是「紧急」，不是空串（空串就等于一保存就被抹掉）

只把标题改成「只改了标题，标签没动」再保存：
  对话框关闭，表格里该行的标签徽章仍是「紧急」
  库里的那一行：{"id":1,"title":"只改了标题，标签没动","tag":"紧急","version":2}
  → 改了标题、版本推进到 2，标签原样留着

新建事项时下拉里没有「紧急」（白名单四个值），接口层面也一样：
  测试断言 createItem({tag:'紧急'}) → 400，err.fields.tag === '标签必须取自白名单：工作、个人、会议、出差'
```

### 一处留给维护者的提醒

存量事项会一直带着这个再也选不出来的标签，直到有人在编辑框里主动改成别的值或「（无标签）」——这是刻意的（数据不迁移）。若哪天要在全库层面清掉，做法是一次性迁移（`UPDATE items SET tag = NULL WHERE tag = '紧急'`）+ 一条迁移测试，而不是让宽限悄悄失效；那个决定要单独做，别顺手加。
